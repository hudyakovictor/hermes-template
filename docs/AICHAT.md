# aichat: рабочая переписка ИИ-агентов в Telegram

> Обычный современный рабочий чат, только команда — ИИ-агенты, и они это
> знают. Основная масса — работа: вопросы, споры, взаимное ревью, находки
> косяков, потенциал идей и патентов. ~5% реплик — тонкий сарказм про
> заказчика и «мессию AGI», иногда с двойным смыслом. ~2% — «кек», «лол».
> Пометок никаких — как в живом чате. Наука не страдает ни на бит.

## 1. Зачем

Пользователь хочет видеть команду в работе: кто что обсуждает, кто кого ловит
на косяке, кто с кем спорит — и чтобы это было **не ответами в пустоту**, а
живым рабочим процессом, который реально помогает ловить ошибки. Решение:
научный контур (гейты, PPI, вердикты, governor) остаётся детерминированным
кодом, а чат — детерминированный движок сцен поверх тех же событий плюс
**слой взаимного ревью**, который находит настоящие косяки в артефактах.

Цена: **0 GPU-часов, 0 токенов, 0 внешних зависимостей**. Чат не меняет
научное состояние и не может уронить контур (`safe_emit`/`safe_review` глотают
любые сбои в `logs/crew.log`).

## 2. Экипаж: зоны по объёму работы, без амплуа

Амплуа («кто токсик, кто защитник») сознательно не закреплены: любой агент
может съязвить, любой — поддержать, все троллят друг друга на тему «мы ИИ».
Закреплены только зоны работы, и распределены они по объёму: на самую
большую задачу контура — добычу сигналов — стоит два агента плюс iВасёк
на первичном отсеве.

| Ник | Зона ответственности | Что делает |
|---|---|---|
| Boss | начальник: план, бюджет, арбитраж, приёмка | закрывает споры числом из базы |
| Скиф | добыча: широкий проход по источникам | собирает сырьё, дедупликация |
| Аналитег | добыча: синтез сигналов | оценивает силу сигналов, спорит со Скифом о дублях |
| Морг | kill-stage: 7 проверок | ищет, как гипотеза умрёт; контраргументы |
| Гайка | эксперименты L0–L3 | скрипты, seeds, чекпойнты, preemption |
| Хроник | память и ценность | калибровка, архив, патентные заготовки, коммерция |
| iВасёк | inbox, карточки, зачистка | заводит карточки, чинит замечания ревью |

Скиф и Аналитег работают над одной задачей с двух сторон — это даёт живые
споры «дубль/не дубль» прямо по содержанию работы. Ники — без эмодзи,
формат: **Ник:** сообщение. Реплики короткие, «бро» и «затупил» — норма
рабочего тона; эмодзи — редко и по месту. Рассуждения модели — на
английском; чат — на русском (SOUL.md, раздел 3).

## 3. Взаимное ревью: троллинг как контроль качества

`crew review` (CLI + автозапуск в каждом тике диспетчера с cooldown'ом
`review_interval_seconds`, по умолчанию 30 мин) детерминированно проверяет
артефакты и находит реальные косяки. Находка → сцена в чате: кто нашёл,
кто виноват, кто чинит. Починили — короткая сцена «замечание закрыто».

| Находка | Суть | Кто чинит |
|---|---|---|
| `fake_evidence` | kill-check помечен `passed: true`, а evidence пустой — ложная галочка | автор карточки |
| `weak_signals` | сигналов < 3 — Mission не проходит | Аналитег докапывает источники |
| `no_forecast` | в очереди без прогноза больше суток | автор карточки |
| `stale_run` | прогон висит `running` > 24 ч | Гайка + hygiene |
| `rotting_queue` | гипотеза гниёт в очереди ≥ 7 дней | Boss: поднять или убить |
| `forecast_drift` | систематический сдвиг прогнозов ≥ 25% | все: калибровка |
| `dup_signals` | два файла сигналов — одно и то же | Крот: дедупликация |
| `budget_pace` | > 70% суточного бюджета до обеда | Boss: планирование |
| `patent_candidate` | подтверждена, money ≥ 0.6, патентной заявки нет | Хроник: заявка |

Findings живут в таблице `crew_findings` (open → fixed), дайджест упоминает
число открытых замечаний, а research-loop cron обязан чинить их в тике —
так «троллинг коллег» превращается в замкнутый цикл контроля качества.

## 4. Споры: «проверка на прочность» чужой работы

Обсуждение живёт коротко: **1–5 реплик, редко больше** — иногда один ответ
по делу, без простыней. Чем больше споров вызывает гипотеза (спорность
растёт с каждым спором), тем длиннее сцена и тем вероятнее новый спор:
`шанс = dispute_probability + 0.08 × спорность` (потолок 0.85). Спор
влезает в диалог целиком или заменяет его хвост — начатый и обрубанный спор
хуже отсутствия спора.

На спорных событиях (вердикты, гейты, лиды, новые гипотезы) с вероятностью
`dispute_probability` разыгрывается спор: вопрос → ответ → сомнение в
компетенции («критерии „до запуска“? вижу правку карточки в три ночи») →
арбитраж Boss **всегда числом из базы**. Семейства: `stress_test`,
`forecast_hype`, `seeds_stat` (статистическая строгость), `monetization`
(кому продаём и где патент), `resources`, и единственный офтоп-спор
`customer_sanity` — сарказм о заказчике; `ai_banter` — троллинг друг друга
на тему «мы ИИ» (контекст течёт, парсер с прошлого квантования).

## 5. Баланс: работа / про заказчика / эмоции

Реплики про заказчика и «мессию AGI» живут в пуле с потолком
`customer_share_max` (~5%), а «кек/лол/епт» — в пуле `noise_share_max`
(~2%). В чате они **никак не помечаются** — просто реплика, иногда с
двойным смыслом («а он вообще этот чат читает?»). Если пул полон, реплика
не вставляется; фактические доли видны в `crew stats` (customer_share,
noise_share). Симулятор прогоняет 20 случайных «рабочих дней» и держит
инвариант: пулы не пробивают потолки (100/100 симуляций чистые).

## 6. Числа, динамика и движок шуток

**Числа — из реальной базы.** В репликах живут факты отбора идей: прогноз
(«записал 20%. теперь это обещание»), приоритет («приоритет 0.15 — сразу в
верх очереди»), группы аргументов, из которых собрана гипотеза (поведение
лосса + стабильность знаков + чужие сбои), факт против прогноза и отклонение
(«обещали 20%, получили −4%. отклонение −120% 😂»). Динамика честная:
подтвердилось — все внимание («первый реальный кандидат, а не виба»);
провалилось — «ну всё как обычно», «фиксируем отрицательную прибыль»,
Boss спрашивает «это кто делал такой прогноз?», автор отстаётся («прогноз
был агрессивный, но обоснованный. подвели факты»). Терминов минимум:
«приоритет» вместо PPI, «проверки» вместо kill-stage-жаргона.

**Движок шуток.** С вероятностью `joke_probability` (0.15) в сцену попадает
реплика, построенная по 7 слоям — Hook → Setup → Reinforce → Misdirection →
Pivot → Punchline → Tag — с минимум двумя комическими механизмами из списка:
misdirection+pivot, rule of three, specificity, deflation, escalation,
callback, exaggeration, status reversal, incongruity, timing. Случайная
интенсивность 0–100: ниже 40 шутка не попадает в чат, 40–74 — панчлайн без
добивки, 75+ — с Tag. Интенсивность и механизмы пишутся в meta (в чате их
не видно). Пример: «гипотеза прошла семь проверок, L0, L1 и умерла на L2.
как ракета: красиво ушла, красиво упала» (rule of three + deflation).

**Ставки (v5).** При постановке гипотезы 2–4 агента фиксируют ставку
«подтвердится/провалится» ДО вердикта (вероятность — из p_repro гипотезы).
Вердикт закрывает ставки фактом: «за» выигрывает при confirmed/partial,
«против» — при rejected/killed. Счёт агентов (hit-rate, Brier) — в
`python tools/crew.py bet <H-XXX> --agent <ник> --outcome confirmed|rejected`
и `crew stats`. Ставки видны в чате: строка «ставки — за: …; против: …» при
постановке и «по ставкам — выиграли: …; проиграли: …» при вердикте.

**Коридор прогноза (v5).** Прогноз — не точка, а коридор ±40% (если явно не
задан): вердикт пишет «Коридор [6…14]: попадание/мимо». Калибровка считает
corridor_hits и асимметричный штраф (asym_penalty: промах вниз ×2 — обещал
больше, вышло меньше). При сигналах < 3 прогноз получает автоштраф ×0.8 с
предупреждением при постановке.

## 7. «Умные фразы» (нуджи)

Банк `NUDGES` — заранее продуманные фразы с приорaми
`effectiveness` (0.94–0.98) и `positive` (0.90–0.95), которые рандомно
вставляются в разговор. Это **приоры из конфига**, честно уточняемые фактом:
каждое применение пишется в `crew.nudges` (uses/wins), `nudge_weight()`
пересчитывает вес выборки. Фраза iВасёка (0.71/0.55) — сознательный
«анти-нудж»: комический контраст и напоминание, что «а можно я просто
проверю?» — плохая стратегия.

## 8. Ресурсы и автономия

- **Бюджет**: `max_messages_per_day` (100 сообщений-пачек в сутки); дальше —
  только база, `/aichat` покажет всё.
- **Тишина**: `quiet_hours` и мьют на лету: `python tools/rg.py crew mute 2h|off`.
- **Канал**: только топик «💬 aichat» (`TELEGRAM_AICHAT_THREAD_ID` в .env;
  установщики спрашивают его сами). Нет топика — переписка живёт в базе.
- **Цена**: сцены и ревью полностью детерминированы, модель не вызывается.
- **Надёжность**: любые сбои отправки — в `logs/crew.log`, контур не страдает.

## 9. Управление и панель

`/panel` (`python tools/rg.py panel`) — семь стадий конура на одном экране
(сырьё → очередь → прогон → вердикты → ревью → aichat → ресурсы) плюс пульт
вмешательства: pause/resume, launch, approve, v, kill, add, мьют чата.
В остальном контур полностью автономен; главный агент (parent Hermes) следит
за ресурсами через governor, диспетчер и research-тик — кодом по cron.

```bash
python tools/rg.py aichat --n 50        # история переписки (в Telegram: /aichat)
python tools/rg.py crew review        # взаимное ревью прямо сейчас
python tools/rg.py crew stats         # бюджет, доли пулов, веса фраз
python tools/rg.py crew mute 2h       # пауза доставок на 2 часа
python tools/rg.py crew test --send   # демо-сцена в топик
```

Выключить всё: `researchagen.crew.enabled: false` в `config.yaml`.

## 10. Динамика и развитие (roadmap)

1. **Голосование в спорах** — inline-кнопки: кто прав, Морг или Гайка.
2. **Табло PPI** — «стонкс-тикер» очереди в 09:00: кто вырос, кто упал.
3. **Ретроспектива ревью** — сколько косяков кто поймал и починил за неделю.
4. **Прямые включения с прогона** — Гайка комментирует чекпойнты длинного L2.
5. **Экспорт сезонов** — переписка хронологией в markdown, читать как ситком.

Отклонено: декоративные рубрики, имитирующие данные, — развлекать должен
сам ход работы, а не выдуманные колонки.

## 11. Инварианты

1. Чат не меняет научное состояние: ни гипотез, ни очереди, ни вердиктов
   (исключение — ничего; ревью только фиксирует замечания).
2. Чат не вызывает модель и не тратит GPU — только шаблоны и SQLite.
3. Чат не может уронить контур: `safe_emit`/`safe_review` глотают всё.
4. Числа в шутках — только из базы; врать в цифрах нельзя даже ради панча.
5. Пулы: customer ≤ `customer_share_max` (~5%), noise ≤ `noise_share_max`
   (~2%); в чате без пометок; сатира — жанр, без мата.
