## Почему не 100

Две неполные оценки поставлены сознательно:

- **Фактор 4 (6.5/7).** Формат тем и богатых сообщений зависит от версии шлюза;
  часть ключей взята из проектных документов архива, а не из живой документации.
  Сбой такого ключа не ломает контур: сообщения уйдут в общий чат.
- **Фактор 11 (7.5/8).** Цели, циклы и канбан встроены и задокументированы, но проверены
  только по документации, без запуска на живом узле.

Завышать эти два пункта до 100 было бы тем самым самообманом, против которого построен
весь остальной проект.

## Как проверить оценку самому

```bash
python -m unittest discover -s tests -q     # логика приоритетов, гейтов, вердиктов
python -m compileall -q tools                # синтаксис всего инструментального слоя
python tools/selfcheck.py all                # среда, токен, модель, изоляция
python tools/rg.py status                    # очередь и бюджет
grep -rn "import " tools | grep -v "^tools/" # ни одного внешнего пакета
```

## Что не проверено в среде сборки

Честный список — это не недостаток, а часть приёмки:

1. Реальные прогоны на RTX 5090 и фактическое потребление VRAM.
2. Скорость и качество Qwen3-27B Q6 с KV-cache Q8 на 25-минутных тиках.
3. Живой Telegram-бот: доставка в темы, меню команд, права двух пользователей.
4. Регистрация cron через настоящий бинарник `hermes` и совместная работа двух профилей.
5. `hermes profile install` из опубликованного GitHub-репозитория.
6. Сами научные гипотезы: контур готов их проверять, но ни одна пока не проверена.

Первый шаг после установки — закрыть пункты 1–4 одним вечером на самой дешёвой
гипотезе из корзины P1.
