# Telegram: штаб двух пользователей

## Архитектурное правило

На один токен — ровно один процесс, который читает сообщения. Поэтому:

- **Управление** идёт через штатный шлюз Hermes: `researchagen gateway start`.
- **Телеметрия** идёт через `tools/tg.py` — только отправка (Bot API `sendMessage`),
  никакого чтения обновлений.

Второго бот-движка в проекте нет сознательно: его некому сопровождать, а конфликты
long-polling диагностируются тяжело.

## Темы (topics)

Создайте группу с включёнными темами и добавьте обоих пользователей:

| Тема | Что туда падает |
|---|---|
| Штаб | Сводки, ответы на команды, запросы подтверждения |
| Прогоны | Старт/финиш/вытеснение экспериментов, промежуточные метрики |
| Вердикты | Факт против прогноза, убитые гипотезы, заготовки патентов |
| Лиды | Идеи от людей (`/idea`, `/add`) и решения по ним: очередь или лог неэффективных |
| 💬 aichat | Рабочая переписка экипажа ИИ-агентов: обсуждения, споры, взаимное ревью косяков; ~5% реплик — тонкий сарказм про заказчика и AGI (`tools/crew.py`, `/aichat`) |

thread_id темы «aichat» кладётся в `TELEGRAM_AICHAT_THREAD_ID` (.env, спрашивают
установщики). Нет топика — переписка пишется только в базу и доступна через
`/aichat`; контур от этого не страдает. Бюджет: `crew.max_messages_per_day`
(30) плюс `quiet_hours` и `crew mute 2h`. Подробности — `docs/AICHAT.md`; панель всех стадий — `/panel` (`docs` в README).

`thread_id` темы «Штаб» указывается в установщике и идёт в `TELEGRAM_CRON_THREAD_ID`.
Остальные темы необязательны: если тем нет, всё идёт в общий чат.

## Меню команд (BotFather → /setcommands)

```
status - Состояние: очередь, прогоны, GPU, бюджет
pool - Очередь гипотез по PPI
next - Одно следующее действие
launch - Запустить уровень для гипотезы
approve - Подтвердить дорогой прогон
pause - Остановить новые запуски
resume - Вернуть автозапуск
v - Закрыть гипотезу вердиктом
add - Предложить идею в inbox (сырой лид)
idea - Идея на разбор экипажу: обсуждение, оценка, очередь или лог
ideas - Очередь идей и лог отклонённых (дубли видны сразу)
digest - Сводка сейчас
gpu - Свободная VRAM и лимиты
doctor - Самопроверка контура
chat - Переписка экипажа: споры, ревью косяков, некрологи
```

## Почему два пользователя видят одно и то же

Ответы на `/status`, `/pool`, `/next` строятся не из контекста диалога, а из единого
`state/researchagen.sqlite3`. Кто бы ни спросил и когда — цифры одни и те же.

Когда действие одного пользователя меняет планы (пауза, подтверждение, вытеснение),
в сообщении называется инициатор — иначе второй человек будет искать ошибку
в коде вместо того, чтобы спросить коллегу.

## Сколько шума допустимо

Исследовательские тики (каждые 25 мин) **не** пишут в чат. В Telegram попадают только
события: запуск, завершение, вердикт, убитая гипотеза, запрос подтверждения, сводка.
Агент, который пишет каждые 25 минут, через день получает отключённые уведомления —
и телеметрия теряет всякий смысл.

## Если бот молчит

1. `python tools/selfcheck.py all` — там есть проверки токена и чата.
2. `logs/telegram.log` — отказы Bot API с кодами ошибок.
3. Типичные причины: бот не добавлен в группу; chat_id без минуса для супергруппы;
   тот же токен, что у первого агента; шлюз не запущен.
