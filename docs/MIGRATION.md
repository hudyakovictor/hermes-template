# Что взято из шаблона и двух версий, а что выброшено

Исходный шаблон при аудите получил **26/100**. Поэтому код не починен, а написан
заново. Сохранены только те идеи, которые выдержали проверку.

## Сохранено

| Идея | Почему осталась |
|---|---|
| 8 kill-проверок гипотезы (8-я — «Кому продадим») | Главный экономитель GPU-часов во всём проекте |
| Каскад L0–L3 | Правильная форма дешёвой фальсификации |
| Формула силы сигнала | Прямо отвечает миссии: искать необъяснённое, а не популярное |
| Структура карточки гипотезы | Жёсткие секции не дают превратить идею в эссе |
| Запрет оценочных слов | Теперь это проверка в коде и тест, а не просьба в промпте |
| Идея индекса приоритета | Переработана: PI → PPI, т.е. ценность на GPU-час |

## Выброшено

| Что | Причина |
|---|---|
| Невалидные ключи `config.yaml` | Выдуманные поля молча игнорируются — иллюзия настройки |
| Конституция, которая никуда не подключалась | Правила, которые не видит агент, не существуют. Теперь — `.hermes.md` + `hooks/BOOT.md` |
| Отсутствие очереди | Без очереди приоритет решался настроением модели |
| `mcp-research-data` | В архиве лежали данные бенчмарка, не имеющие отношения к миссии |
| Собственный Telegram-бот на long-polling (v1) | Второй процесс на тот же токен ломает оба |
| Ошибки CLI и учёта VRAM в `experiment_runner` | Вместо `memory_allocated()` читается реальная свободная память устройства |
| Рубрика «оцени себя сам» в промпте | Заменена калибровкой по фактическим вердиктам |
| Ссылка на неработающий установщик | Два своих установщика без зависимостей |
| Устаревшая предметная часть | Цели и фокус переписаны под актуальную миссию |

## Главный сдвиг мышления

В предыдущих версиях дисциплина жила в тексте инструкций: модель просили быть
строгой. Здесь дисциплина живёт в коде: гейты в `dispatch.py`, отказы в `verdict.py`,
лимиты в `calib.py`, проверки в `selfcheck.py` и `tests/`. Модель может забыть
инструкцию — код не забывает.
