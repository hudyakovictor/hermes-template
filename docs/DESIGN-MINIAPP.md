# Дизайн-спецификация Mini App: «Тёмная лаборатория»

Документ фиксирует структуру и визуальный язык Mini App (папка `miniapp/`).
Реализация самодостаточная: без сборщика, без внешних пакетов, экран 390×844
как базовый, адаптив от 320 до планшета.

## 1. Концепция

Мобильный пульт управления автономной лабораторией. Три принципа:

1. **Правило 3 секунд** — статус контура читается без скролла: кольцо VRAM,
   режим АВТО/ПАУЗА, прогресс текущего прогона, остаток бюджета.
2. **Один тап для вмешательства** — пауза/резюм, одобрение L3, приоритет.
   Критичное (снять прогон, закрыть гипотезу, вытеснить) — с защитой:
   **hold-to-confirm 1.1 с** с заполняющимся индикатором, вибрацией и
   объяснением последствий («чекпойнт сохранится, прогресс уровня пропадёт»).
3. **Наука как драма** — гипотеза живёт на экране как объект с судьбой:
   рельс каскада L0→L3, коридор прогноза, споры и ставки экипажа, вердикт
   «обещали vs получили».

## 2. Визуальный язык

| Токен | Значение | Смысл |
|---|---|---|
| Фон `#0a0d13` + карточки `#121826` | тёмная лаборатория, радиус 18px | терминал-эстетика без «неона» |
| Акцент `#4fc3ff → #8b7cff` | градиент действия | все интерактивы — только он |
| Уровни каскада | L0 серо-синий, L1 циан, L2 фиолет, L3 золото | цена часа растёт — цвет «дорожает» |
| Статусы | подтверждено `#3be0a0`, отвергнуто `#ff6161`, убито — приглушённый серый | убитая до GPU идея — не ошибка, а результат |
| Числа | моноширинный шрифт, tabular-nums | PI/PPI/градусы/часы — язык пульта |
| Живое | пульсирующие точки, стрим-полоса на прогрессе, ping у соединения | контур «дышит» |

Тема наследуется из Telegram (`themeParams` → CSS-переменные), включая
light-схему; графики читают палитру из CSS на каждом кадре.

## 3. Сетка и навигация

- Низ: 5 табов + центральная FAB «+» (подача идеи — главное действие человека).
- Шторки (bottom sheet) для всего, что глубже одного экрана: карточка
  гипотезы, вердикт, сравнение прогонов, подтверждения, форма идеи.
  Свайп-вниз по «ручке» закрывает, BackButton Telegram связан со шторкой.
- Каждый экран — свой скролл-контейнер с pull-to-refresh (спиннер + хаптика).
- Тосты — вместо блокирующих диалогов; критичные подтверждения — только шторки.

## 4. Разделы задания → экраны

### 4.1 Dashboard & Hardware → «Пульт»
Кольцо VRAM (SVG-градиент, анимация смещения), температура/кулер/утилизация,
спарклайн утилизации за 60 с; бюджет-бар с прогнозом «лимит в HH:MM»;
карточка текущего прогона (уровень, %, ETA, seeds); баннер «нужно подтверждение
L3» с кнопками Одобрить/Отклонить; лента событий контура; быстрая пауза в
топбаре. Действия: пауза/резюм (1 тап), снятие прогона (удержание), одобрение.

### 4.2 Pipeline & Lifecycle → «Конвейер»
Рельс L0→L3 со счётчиками и «протекающими» перемычками; сегменты
Очередь/На GPU/Пауза/Закрыто; карточки очереди по PPI с корзиной P1–P4,
свайп влево → быстрые действия (выше / L0 / закрыть). Шторка гипотезы:
механизм, разбор PI по весам S/N/E/Q/M/D (+aging) как в `tools/queue.py`,
коридор эффекта (зона min–max с зелёным коридором и точкой прогноза),
8 kill-проверок с состояниями. Запуск L0 при занятом GPU → шторка выбора:
«в очередь первым» или «вытеснить» (удержание).

### 4.3 Live Telemetry → «Телеметрия»
Canvas-графики без библиотек: loss по трём сидам с grokking-ступенями,
effective rank, разброс сидов (CV%); тултип по касанию с перекрестием;
log-шкала; легенда-переключатели; наложение до 3 прогонов из истории;
спарклайны ‖grad‖, lr, VRAM. Живой стрим синхронен прогрессу прогона.

### 4.4 Crew & Prediction Market → «Экипаж»
Чат: аватары-цвета агентов, зоны ответственности, системные события-пилюли;
спор-блок с темой, аргументами, сплит-баром и голосованием человека
(арбитраж Boss приходит сообщением позже). Рынок: открытые ставки с
аватарами «за/против», ставка человека, рейтинг точности со стриками,
рассчитанные ставки. Ревью: замечания взаимного контроля сseverity-полосами
и статусом «открыто/закрыто».

### 4.5 Idea Intake & Triage → FAB «+»
Три шага с прогресс-полосой: Механизм → Метрика и тест → Рынок.
Динамическая дедупликация: пауза набора 650 мс → проверка против закрытых
идей → карточки схожести с %, причиной закрытия и красным «почти дубль»
при >80%. Мгновенный фидбек: 5-полосный метр качества формулировки
(конкретика, числа, доменные термины). Шаг 3 — орб-индикатор симуляции
PI/PPI и прогноз места в очереди. Отправка → карточка H-0XX в конвейере,
реакция iВасёка в чате.

### 4.6 Verdicts & Outcomes → «Итоги»
Донат калибровки «прогнозов в коридоре»; фильтры по статусам; карточки с
двойными барами «обещали vs получили», коридором и дельтой («в коридоре» /
«мимо на X»); шторка вердикта: факт против зафиксированного прогноза, урок
в память, проверка соседей на дефект, патентная линия; экспорт отчёта в
буфер (готов к вставке в чат лаборатории); заготовки патентных claim'ов.

## 5. Интерактивные паттерны (чеклист)

- Хаптика: смена таба (selection), действия (light/medium), ошибки (rigid),
  успех вердикта (success-нотификация) — через `HapticFeedback`.
- Hold-to-confirm на: снять прогон, закрыть гипотезу, вытеснить прогон.
- Свайп-строки очереди; тап-по-карточке — шторка; свайп-вниз — закрытие шторки.
- Pull-to-refresh на всех экранах; skeletons на загрузке; анимации входа
  сообщений; flash-подсветка обновлённых блоков; FLIP-free ререндер с
  soft-переходами; `prefers-reduced-motion` уважается глобально.
- Числа анимируются, времена — относительные («4 мин назад») с автообновлением.
- Empty-состояния с подсказкой следующего действия.

## 6. Доступность и надёжность

- Контраст текста ≥ 4.5:1 в обеих схемах; размеры касаемых целей ≥ 44px
  (кнопки 46px, иконки-кнопки 36px с полем).
- `aria-label` на иконочных кнопках, `role=dialog` у шторок.
- Вся логика данных отделена от UI (`static/data.js`, шина событий):
  продакшен-мост к `state/researchagen.sqlite3` заменяет один модуль.
- `serve.py`: stdlib, no-store для HTML, защита от path traversal,
  read-only доступ к SQLite (`mode=ro`).

## 7. Дорога к продакшену (за пределами демо)

1. `serve.py` → FastAPI/stdlib-эндпоинты поверх SQLite: `state`, `queue`,
   `verdicts`, `chat`, `telemetry` (последний — SSE или опрос раз в 1–2 с).
2. Действия пользователя отправлять не в Bot API напрямую, а через CLI-обертки
   `tools/rg.py` (единая точка входа без модели) — инварианты governor'а
   сохраняются.
3. Авторизация: `initData` Telegram валидируется на сервере (hash =
   HMAC-SHA256 токена бота), whitelist двух `user_id` из `.env`.
4. Телеметрия прогонов: `results/<H>/<level>/metrics.jsonl` → кольцевой
   буфер последних N точек.
