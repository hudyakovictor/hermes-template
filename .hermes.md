# researchagen — рабочие правила проекта

Этот файл — проектный контекст с высшим приоритетом (`.hermes.md` → `AGENTS.md` → …).
Личность — в `SOUL.md`, домен — в `FOCUS.md`, миссия — в `MISSION.md`.

## 0. Ориентация за 10 секунд
```
researchagen/
  FOCUS.md          домен (единственное место, где он живёт)
  state/            SQLite: очередь, вердикты, калибровка, сессии  (не в git)
  signals/          найденные сигналы (md, по одному на сигнал)
  hypotheses/       H-XXX.yaml — карточки гипотез
  experiments/      EXP-XXX.py + results/  (артефакты запусков)
  inbox/            зацепки от человека, ждут следующего тика
  memory/           уроки: почему гипотеза умерла, где ошибся прогноз
  reports/          дайджесты, session debrief, патентные заготовки
  tools/            python-stdlib CLI (без внешних зависимостей)
  skills/           slash-команды агента
  tools/bottom_detection/  гибридный слой регионального поиска
```
Все инструменты запускаются одинаково: `python tools/<name>.py <cmd> [args] [--json]`.
Для Bottom Detection единая точка входа — `python tools/rg.py bottom <cmd> [--json]`;
проверка stdlib-only coverage — `python tools/bottom_coverage.py`.
Состояние читай через `python tools/rg.py status`, а не через догадки.

## 1. Инварианты (нарушать нельзя)
1. **FOCUS.md — единственный источник домена.** Не хардкодь домен в скиллах, промптах и гипотезах.
2. **Очередь — единственный источник порядка работ.** Что запускать, решает `tools/dispatch.py next`, а не желание «сделать интересное».
3. **PASS/FAIL до запуска.** `tools/hypo.py check H-XXX` обязан вернуть `ok` перед `launch`. Нет критериев — нет GPU.
4. **Каждый уровень заканчивается checkpoint'ом.** Между уровнями возможен preempt; внутри уровня — нет.
5. **Прогноз фиксируется в карточке.** Вердикт всегда сравнивается с прогнозом; расхождение уходит в калибровку.
6. **Артефакт или ничего.** Ход без записи в `state/`, `signals/`, `hypotheses/`, `results/` не считается.
7. **Только stdlib в `tools/`.** Никаких pip-зависимостей: профиль должен ставиться на чистую Windows/macOS.
8. **Ключи только в `.env`.** Ни один токен не попадает в `config.yaml`, логи, отчёты и Telegram.

## 2. Автономный контур (R1–R16)
- **R1** DEEP_RESEARCH крутится короткими тиками: cron `research-loop` каждые 25 мин, одна фаза за тик.
- **R2** Очередь пуста (< 3 живых гипотез) → эксперимент не запускается, идёт research. Дешёвая гипотеза через час лучше дорогой сейчас.
- **R3** GPU свободен и живых гипотез ≥ 3 → взять `dispatch.py next`: сначала лучший PPI среди P1/P2, иначе лучший PI с учётом aging.
- **R4** Автозапуск включён по умолчанию (`/auto off` — только ручной `/launch`).
- **R5** Зацепка человека → `inbox/` → оценка PI на следующем тике. Текущий ход не прерывается.
- **R6** PREEMPTION: на checkpoint'е сравни свой PI с лучшим в очереди. Если тот ≥ 2× — статус `paused_checkpoint`, GPU отдаётся, чекпоинт сохраняется.
- **R7** Запуск дороже `limits.approval_gpu_hours` (по умолчанию 12 ч) — только после `/approve` в Telegram.
- **R8** 09:00 — дайджест в топик «Штаб»; вс 20:00 — пересчёт весов PI по калибровке; 03:30 — hygiene (ротация логов, sanity очереди).
- **R9** Любая ошибка тика пишется в `logs/` и в дайджест, но не останавливает контур: следующий тик читает состояние заново.
- **R10** Ничего не удаляй безвозвратно: `archive`, а не `delete`.
- **R11** Parent Hermes — единственный governor. Перед native `delegate_task` он вызывает `governor plan` и `reserve`; child не делегирует дальше, не меняет SQLite и возвращает только структурированный отчёт.
- **R12** В `discover` capacity = min(config cap, режим, свободная VRAM после experiment reserve, telemetry cap, остаток research budget, число независимых задач). Если `queue.pick_next` уже прошёл kill-stage, testing priority сразу делает research capacity `0`. При high util/low VRAM путь деградирует `2 → 1 → 0`; неизвестная production-телеметрия = `0`.
- **R13** `testing` — эксклюзивный GPU lane: новые research/Qwen leases запрещены, research cron ставится на паузу, активные workers получают `pause_requested` и должны быть остановлены/доведены до checkpoint до запуска.
- **R14** `analyze` остаётся после `finish`; следующий эксперимент и resume research запрещены до явного `/v` и анализа результата.
- **R15** `delegate_task` — только короткие reasoning-heavy листья. Для механических циклов используй `execute_code`, для durable handoff — native Kanban; это не повод увеличивать fan-out.
- **R16** Summary child не меняет scientific state. Отчёт проходит `governor report`, затем parent сам проверяет sources/evidence, deduplicates claims и только после этого создаёт/promotes гипотезу.

## 3. Как использовать движки Hermes (не изобретать свои)
| Механизм | Когда |
|---|---|
| `/loop 25m …` | внутрисессионный мониторинг: следить за идущим экспериментом, «дожать до зелёного». Self-paced (`/loop` без интервала) — для ожидания без затрат. |
| `/goal` + `verify:`/`gate` | одна задача с определением done: «довести H-012 до вердикта L1». Gate — детерминированная проверка (`python tools/hypo.py check H-012`). |
| `/goal wait` | ждать фоновый прогон вместо busy-poll. Всегда запускай обучение через `terminal(background=true, notify_on_complete=true)`. |
| cron | всё, что должно жить без сессии: research-loop, dispatcher, digest, recalib, hygiene. |
| kanban | доска для человека и параллельных исполнителей; зеркалится из очереди (`tools/board.py sync`). |
| memory | только уроки и калибровка, не пересказ фактов. |
| `session_search` | прежде чем «открыть» сигнал — проверь, не закрывал ли ты его месяц назад. |
| subagent / `delegate_task` | короткий bounded research fan-out только после `governor plan/reserve`; при testing — запрещён. |
| `execute_code` | механический сбор, фильтрация, дедупликация и агрегация без LLM worker. |
| native Kanban | durable handoff между профилями/перезапусками; worker всё равно обязан пройти governor lease. |

**Правило разделения:** `/goal` — одна цель в этой сессии; `/loop` — таймер в этой
сессии; cron — жизнь вне сессий. Активный `/goal` владеет сессией, wakeup'ы
`/loop` ждут — поэтому не ставь их на одну и ту же работу.

## 4. Стоимость и железо
- Основная площадка: Windows + RTX 5090 (32 GB), Qwen3-27B Q6, KV-cache Q8 через Ollama.
- macOS — отладочный контур: `platform=darwin` → эксперименты идут в `--dry-run`, GPU-гейты имитируются, Telegram-бот работает полностью.
- Перед любым запуском: `python tools/gpu.py check --need-gb N` (реальная свободная память, а не «total − allocated»).
- Для research workers перед каждым `delegate_task`: `python tools/rg.py governor plan --tasks N --json`, затем одна lease на каждый logical task. Планировщик выбирает N сам; не запрашивай фиксированный swarm.
- В testing governor блокирует новые Qwen-вызовы и сохраняет experiment reserve; `dispatch.py` не запускает эксперимент, пока research leases не перешли в `paused/stopped/released`.
- Модель локальная и слабее облачной: держи ходы короткими, не грузи в контекст сырые логи — читай их через `tail`/`jq`-подобные срезы и summary-файлы.

## 5. Стиль вывода в Telegram
Таблица очереди — таблицей (rich messages), а не буллетами. Числа — с единицами.
Один экран = один смысл: очередь / вердикт / прогресс. Длинные тексты — файлом
(`MEDIA:`), не десятью сообщениями. Пуш — только на вердикты и подтверждения.

## 6. Definition of Done для любого хода
- [ ] артефакт записан на диск;
- [ ] `python tools/rg.py status` отражает новое состояние;
- [ ] названо следующее действие и почему именно оно;
- [ ] если что-то не проверено — это сказано явно.
