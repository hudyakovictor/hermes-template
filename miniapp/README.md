# researchagen Mini App — пульт автономной ИИ-лаборатории

Telegram Mini App для наблюдения и управления контуром: то, что раньше требовало
десятка слеш-команд текстового бота, теперь укладывается в три секунды взгляда
и один тап.

> Философия профиля сохранена: **ноль внешних пакетов**. Сервер — Python stdlib,
> фронтенд — vanilla JS + canvas, без сборки и npm.

## Что внутри (6 зон брифа)

| Зона брифа | Экран | Ключевое |
|---|---|---|
| 1. Dashboard & Hardware | **Пульт** | GPU (util / VRAM с порогами / температура), суточный бюджет часов и задач, текущий прогон с ETA и loss к базовой кривой, пауза/продолжить, снятие задачи **удержанием 1.2 с**, подтверждение дорогих прогонов (двойной тап на отклонение) |
| 2. Pipeline & Lifecycle | **Конвейер** | очередь по PPI, корзины P1–P4, лестница каскада L0–L3, kill-чеки (8 проверок до GPU) с ручным запуском, коридор эффекта, приоритет (aging), запуск уровня вручную |
| 3. Live Telemetry | **Графики** | калибровка прогнозов: «обещали vs получили» по закрытым вердиктам (canvas, перекрестие по касанию), таблица отклонений; при активном прогоне — статус и elapsed из диспетчера |
| 4. Crew & Prediction Market | **Экипаж** | живой чат 7 агентов (`crew.py replay`), споры — арбитраж Boss (человек наблюдает), взаимное ревью (`crew.py review`), открытые ставки «взлетит/не взлетит» и рейтинг точности (hit-rate, Brier) из счёта ставок |
| 5. Idea Intake & Triage | **＋ Идея** (визард) | качество формулировки в реальном времени (включая запрет «перспективно/многообещающе» — как в `verdict.py`), симуляция PI/PPI **той же формулой, что решает очередь**, проверка на дубликаты с процентом сходства, место в очереди до отправки |
| 6. Verdicts & Outcomes | **Вердикты** | «что обещали vs что получилось» (dumbbell + отклонение %), seeds, GPU-часы, коммерческий потенциал, проекты патентов, экспорт отчёта (share/буфер), фильтры |

Метрики не выдуманы: PI/PPI считаются по формуле из `tools/queue.py` (веса —
`researchagen.pi_weights` из `config.yaml`), экипаж, kill-чеки и статусы — из
`tools/crew.py`, `tools/hypo.py`, `tools/governor.py`, `tools/verdict.py`.

## Запуск

```bash
python3 miniapp/server.py --port 8787   # порт также задаётся переменной PORT
```

Открыть `http://localhost:8787`. Вне Telegram приложение работает полностью —
отличается только отсутствие хаптики и нативной кнопки «Назад».

### Только live, без демо-данных

Демо-режим удалён полностью. `/api/state` читает живой профиль через штатные
CLI контура (`tools/rg.py status`, `tools/queue.py list --all`,
`tools/verdict.py list`, `tools/gpu.py show`, `tools/crew.py replay/review/stats`,
`tools/rg.py bets/ideas`) плюс read-only SQLite. Пустая база — честные пустые
состояния. Воздействия идут теми же CLI, что у бота: pause/resume/kill_task/
approve/launch/check/idea; голосование в спорах отключено — споры закрывает
арбитраж Boss.

## Подключение к Telegram

1. Поднять сервер так, чтобы он был доступен по HTTPS (домашний узел:
   `cloudflared tunnel --url http://localhost:8787` или reverse-proxy с TLS).
2. BotFather → `/newapp` (или `/setmenubutton`) → указать URL.
3. Открыть Mini App из меню бота. Тема, хаптика, BackButton и MainButton
   подхватятся автоматически; вне Telegram всё деградирует мягко.

Разрешённые пользователи — те же, что в `TELEGRAM_ALLOWED_USERS` профиля:
проверку `initData` делает обёртка на вашем прокси, либо добавьте проверку
HMAC по документации Telegram (в stdlib это `hmac` + `urllib.parse`).

## Структура

```
miniapp/
  index.html      оболочка, таббар, FAB
  app.css         дизайн-система (тёмная, themeParams-маппинг)
  js/charts.js    движок графиков на canvas: линии, коридоры, перекрестие, спарклайны
  js/app.js       экраны, щиты, визард идеи, Telegram WebApp SDK
  server.py       static + /api/state + /api/action — только live-контур
```

## API

* `GET /api/state` — вся картина одним запросом (GPU, governor, очередь, прогоны,
  экипаж, вердикты, статистика). Фронт опрашивает раз в 4 с и перерисовывает
  экран только при реальном изменении данных (diff-ключ).
* `GET /api/ping` — режим (live).
* `POST /api/action` — воздействия: `pause`, `resume`, `kill_task`, `approve`,
  `boost`, `run_check`, `run_level`, `idea_check`, `submit_idea`, `vote`.
