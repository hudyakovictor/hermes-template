# /v — вердикт

Вердикт — единственный способ закрыть гипотезу. Гипотеза без вердикта висит в `review`
и блокирует очередь — это сделано специально.

## Шаг 1: взять факты из артефактов, не из памяти

```bash
cat results/H-XXX/L1/summary.json
python tools/queue.py show H-XXX
```

Прогноз берётся из карточки (поле `forecast`), зафиксированное ДО запуска.
Если прогноза не было — вердикт невозможен, эксперимент был ненаучным. Запиши
это как `--kind killed` с объяснением.

## Шаг 2: записать

```bash
python tools/verdict.py record H-XXX \
  --kind confirmed|partial|rejected|killed \
  --level L1 --actual 11.4 --seeds-pass 3 --seeds-total 3 \
  --sigma 0.4 --gpu-hours 0.9 \
  --changes "L2 с 5 seeds и двумя архитектурами; новый прогноз 9%"
```

В `--changes` пишется только то, что изменится в действиях. Слова «перспективно»,
«многообещающе», «возможно улучшение», «выглядит интересно» отклоняются инструментом.
Это не стиль, а защита от самообмана.

## Шаг 3: решить судьбу уровня

| Исход | Действие |
|---|---|
| ПОДТВЕРЖДЕНО на L0/L1 | повысить уровень: `queue.py set H-XXX --status queued --level L2`, пересмотреть `est_hours` и новый `forecast` |
| ЧАСТИЧНО | сузить утверждение до той части, которая выдержала; новая карточка, новый прогноз |
| ОПРОВЕРГНУТО | закрыть; вынести урок в `memory/killed.md`; проверить, не падают ли соседние гипотезы на том же допущении |
| Подтверждено на L2/L3 | `python tools/report.py patent H-XXX` — заготовка патентного описания |

Отклонение прогноза > 50% в любую сторону — повод выполнить `/calib`: либо модель
мира кривая, либо измерение кривое — и то, и другое важнее самой гипотезы.

## Шаг 4: отчёт в Telegram

`tools/verdict.py record` уже пишет `reports/verdict-H-XXX.md`. Отправь тот же текст:
`python tools/tg.py send "$(cat reports/verdict-H-XXX.md)"`.
